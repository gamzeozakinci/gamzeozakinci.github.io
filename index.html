05Projects

Gratis.com — Playwright + TestNG UI Automation

End-to-end UI test automation for gratis.com, a large Turkish cosmetics e-commerce site: 30 automated tests across 7 areas, written in Java 17 with Playwright and TestNG using the Page Object Model (7 page objects). It runs against the real, live production site, not a mock or a staging copy, so most of the engineering went into making the tests reliable: OTP-only login, look-alike elements, flaky clicks and a third-party payment widget.

  • 30 test cases
  • 7 areas
  • 3 suites
  • 6 smoke tests

Coverage

  • Authentication (5 tests): OTP-only phone login and registration, wrong-OTP and invalid-phone (repeated digits) validation; the tests that need a real SMS code pause for manual entry.
  • Navigation (4 tests): hover-driven mega menu with URL assertions, mobile hamburger accordion on an emulated 390×844 viewport, basket counter sync and logo redirect.
  • Search (3 tests): autocomplete suggestions verified to contain the typed keyword, valid-keyword results page, empty-results state for a nonsense keyword.
  • Filter & Sort (3 tests): brand filter and sort order verified through URL parameters and the listed products, plus a list re-render check with auto-retrying assertions.
  • Catalog (6 tests): product page layout, image gallery with zoom lightbox, wishlist add/remove through a modal with toast assertions, guest-to-login redirect from three entry points.
  • Cart (6 tests): add from listing and product page, quantity changes, item removal, invalid promo code, persistence after reload and clear-all; dependent tests chained with TestNG dependsOnMethods.
  • Checkout (3 tests): store-pickup and home-delivery flows (city, district, store, address, terms) and an empty-cart guard; stops when the in-page payment modal opens, so no card is used and no order is placed.

Engineering decisions

  • Login without automating the OTP: gratis.com has no password, only phone number + SMS OTP with no sandbox code. A one-time manual capture saves the session cookies with Playwright's storageState, so logged-in tests start already authenticated (the token lasts about 15 minutes, so it is re-captured before a run).
  • Finding the right element: the same element often appears several times on a page (the wishlist link exists four times, only one visible), so locators are scoped to one product card, cart row or dialog, or to the visible copy only.
  • Web-first assertions: auto-retrying assertions (hasURL, hasText, isVisible) rather than guessing at timing.
  • Retry with verification: genuinely flaky actions, such as a header link and the payment step, are retried up to 3 times and the test continues only once the result (URL change or modal) is confirmed.
  • Structure & suites: fresh browser per test, config-driven test data, desktop and mobile viewports, failure screenshots and TestNG HTML reports; full regression, a 6-test tagged smoke suite and a manual auth suite for the OTP tests.
